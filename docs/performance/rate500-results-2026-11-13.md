# Focused 500 Mbps CPU work

## Baseline attribution

All four partial trials validate: two Instruments captures and two separate
operation-counter diagnostics. The 4 GiB, 128-file hybrid fixture uses 256 KiB
pieces and a seed-side loopback limit. The diagnostic interval runs from transfer
start through the durable shutdown gate, including settle, measurement, drain
and persistence. Comparison metrics use only the ten-second window after five
seconds of settling. Instrumented samples are excluded from comparisons.

Butter's capture contains 4,872 Running samples. These disjoint executing-leaf
categories describe calling stacks, not measured kernel residence time:

| Work | Running sample weight |
| --- | ---: |
| Filesystem metadata/open/close | 39.29% |
| Payload I/O | 9.42% |
| Networking | 3.82% |
| Scheduling and event delivery | 3.02% |
| Kernel-facing copying (`vm_copy`) | 2.67% |
| User hashing | 14.86% |
| User copying/clearing | 4.02% |
| User allocation | 2.79% |
| Other processing or unresolved execution | 15.72% |
| Unattributed | 4.39% |

The largest open stack, 13.20%, is `openat` beneath `StorageDirectory.parent`,
`inspect` and `writeOperations`. Another 10.47% is close beneath write cleanup;
2.73% is open beneath the batch's initial target inspection. These are separate
sample stacks, not overlapping inclusive totals. The separate counter run
records 72,931 directory opens, 9,708 payload-file opens, 51 atomic-state opens,
85,816 descriptor duplications and 110,204 descriptor inspections. Its 6,478
write batches contain 50,248 blocks, with 43,750 descriptor-cache hits. Both
hashes process 823,132,160 bytes. Counts cover start through durable; they are
not timing results or directly equal to the differently instrumented capture.

`mach_msg2_trap` includes 1.95% under `vm_copy` in peer input appending and
0.72% under `vm_copy` in storage reads. These are copying stacks, not evidence
of time spent waiting for disk or worker scheduling. Direct storage dispatch
under `__workq_kernreturn` accounts for 0.21%; continuation resumption includes
0.37% with mixed ancestry. Worker ancestry's 71.8% inclusive weight describes
where work executes and is not scheduling overhead. No combined-write/verify
candidate is justified by this capture.

Filesystem inspection remains the largest opportunity, but its dominant path
matches the previously rejected descriptor/parent-cache experiments. There is
no materially different, evidence-supported cache change within the required
replacement, symlink, hard-link, permissions and external-edit protections.
This area is exhausted for this pass; this does not establish that filesystem
optimisation is impossible. Scheduling is likewise exhausted on current evidence.
Hashing/copies receive one isolated direct-leaf-range trial below.
