# Swift/libtorrent comparison — 12 November 2026

The performance target remains unmet.

The final matrix contains 264 trials: 264 accepted and 0 failed, including 36 declared warm-ups. All 18 memory checks pass. Four cases meet the throughput threshold, but CPU fails in every case: paired median CPU ratios range from 3.634 to 9.236. One case extended to twelve measured pairs; every original sample remains in the record.

Candidate: `1309716eb037de8ad85259a248580706f2b8a831`. Baseline: public commit `3a4df887725491d5cad533c9c419b818a8bff20b`, identical to the temporary baseline tree recorded in its environment addendum. The reference remains pinned to `6da363d2994f17c0b3c0450d124cf73a31a73847`.

## Method

The workloads each transfer 1 GiB: one file, 128 equal files, or four simultaneous 256 MiB torrents. Pieces are 256 KiB; v1, v2 and hybrid metadata are tested in both directions. Every engine uses the same libtorrent counterpart, with counterpart CPU, throughput and errors retained separately.

Each case has one warm-up per engine, then six measured pairs in balanced, reproducibly shuffled order. Crossing acceptance intervals extend that case to twelve pairs. Sources are explicitly warm; processes and destinations are fresh. These are APFS measurements on an Apple M1 Max, Mac13,1, 32 GiB, ten logical CPUs. Raw environment records contain the exact OS, compilers, flags, dependency/driver/source hashes, filesystem, resource limits and transport settings.

Acceptance requires verified throughput at least 0.90× libtorrent, CPU seconds/GiB through durable completion at most 1.25× libtorrent, and whole-process Swift peak RSS within 1.10× baseline. Paired median percentile-bootstrap intervals use 10,000 resamples at 95%. Memory uses independent median bootstrap intervals and also checks the observed maximum. Display values are rounded; raw JSON retains full precision. Workloads have no combined average.

A metric whose interval still crosses its threshold after twelve pairs remains inconclusive; a clearly failed CPU target still fails the case. The concurrent v2 download extension resolved its throughput interval above 0.90. No final interval remains unresolved.

Swift retains its production forced completion checkpoint inside its verified interval. Libtorrent reports finished before its persistence barrier. Through-durable metrics include both placements. Both drivers complete payload/state POSIX fsync barriers and save native usable recovery state. Every accepted payload receives an independent streaming SHA256/size check, followed by reopening both saved states to verify completion. Seeding ends when the receiver verifies the payload.

Production request windows remain unchanged. Swift reports its download pipeline and incoming upload quotas; the reference reports its native queue defaults. Encryption and µTP performance are outside this milestone, with correctness covered by the regression suites.

The tool server restarted during many-file v2 seeding. The benchmark processes continued unchanged; no sample was discarded or repeated. The [environment addendum](raw/final-matrix/environment-addendum.json) records this condition.

## Correctness and remaining work

Many-file seeding CPU regressed against the baseline. Independent before/after median-bootstrap ratios are 1.025 [1.014–1.077] for v1, 1.151 [1.134–1.241] for v2 and 1.099 [1.092–1.125] for hybrid. These ratios resample measured Swift runs independently across revisions; they do not assume cross-commit pairing. [All eighteen before/after CPU intervals](before-after-cpu-2026-11-12.json) are retained. The regressions have not been isolated to an individual change and remain open alongside the parity gap; this candidate is not accepted against the performance target.

All 319 package tests passed. AddressSanitizer and ThreadSanitizer each passed 47 focused ownership/concurrency tests. The controller passed eight tests / 40 assertions. The final serial native/reference contracts, lifecycle, process-crash, actual ENOSPC/read-only-volume, interruption, bidirectional TCP/MSE/µTP, reference engine and Debug/Release linkage checks passed.

An earlier combined contract invocation reached its six-second native deadline while sanitizer compilation ran alongside it. Its original failure is retained. Call-site and final-snapshot diagnostics were added without changing the deadline or assertions; subsequent serial checks passed. The original wait point remains unknown.

Final Release profiles retain substantial whole-layout file-stamp/path inspection in many-file downloads. Seeding retains per-block upload tasks, disk-admission actor crossings and Network.framework sends. These measured costs remain open CPU bottlenecks; request windows, cache budgets, hashing and filesystem safeguards were preserved. The target has not been relaxed.

Peer diagnostics are retained separately from trial outcomes. Native records include `torrent finished` disconnects; Swift reset diagnostics occur in 27 concurrent-download trials, including warm-ups. All of those trials passed their payload and recovery checks. Exact per-connection close timing was not captured. The previously reproduced upload-byte-limit disconnect did not recur.
